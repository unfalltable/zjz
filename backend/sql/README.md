# 数据库 SQL

本目录保存商务数据库版本化迁移（`0000_*.sql` 起）和 Drizzle `meta/`。`数据库SQL.sql` 属于其他开发者的用户模块，保留原样，不属于 D1 商务迁移；不得混合执行目录全部 SQL。

新数据库按迁移序号依次执行 SQL；已有数据库仅应用未执行的迁移。不要重复执行所有建表文件，不要修改已应用的历史 SQL 或元数据。

表结构的 TypeScript 定义在 `../api/db/schema.ts`。需要新增或修改表结构时，在仓库根目录执行 `npm run db:generate` 生成追加迁移，检查 SQL 后再通过目标环境的迁移流程应用。2026-10-10 追加了 `0002_commerce_foundation.sql`：商品展示/价格/版本、订单请求摘要/版本及三类审计。仅追加、不回填已有价格/库存、不删表。代码改造未对现有本地或生产数据库应用迁移；部署前需备份并检查 journal，只应用未执行版本。测试用的是隔离内存 SQLite 和非持久化本地 D1。

构建时只将 `meta/_journal.json` 明确引用的 SQLite SQL、对应 snapshot 与 journal 复制到 `dist/.openai/drizzle/`，兼容现有托管约定；该构建输出名称不影响本目录采用 `sql/`。打包器会先验证路径、顺序、普通文件与元数据，缺少源文件即构建失败。`数据库SQL.sql`、README 和未登记 SQL 均不打包，不会误送入 D1。
