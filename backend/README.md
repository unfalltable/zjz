# 服务端

业务逻辑与前端页面分离。当前运行载体仍是 Web 项目的 Cloudflare Worker；这个目录不是第二个正在运行的服务器。

- `db/`：D1 数据访问、数据库表结构、后台库存与订单操作。
- `services/checkout.ts`：输入校验、服务端计价、三种履约路线、幂等保存待付款订单。
- `http/`：供 Flutter / Web 复用的 JSON API。
- `auth.ts`：现有 ChatGPT 站点登录与店主授权。
- `payments.ts`：支付适配器接口，当前强制关闭。
- `drizzle/`：已存在的数据库迁移，迁移内容未修改。

API 路由位于 `web/app/api/v1/`，只做入口转发；业务逻辑留在这里。以后迁移到独立服务可替换运行适配层，不应复制订单规则。

API 采用同源浏览器策略，没有通配 CORS。Flutter 原生客户端可直接请求 HTTPS API；Flutter 浏览器预览应与 Web 同源，或配置同源反向代理。不要在 App 中放数据库、支付、店主或供应商凭证。

正式开放公共 API 前仍须补充边缘限流/反滥用、客户认证与订单访问令牌、监控，以及数据库库存与商城库存的统一。订单号 + 邮箱的查询沿用当前流程，不是完整客户账户系统。
