# 服务端

按 SQL、接口和管理页面分类。接口当前运行载体仍是 Web 项目的 Cloudflare Worker；仅调整源码组织，没有新增独立运行的 API 服务器。

- `sql/`：数据库建表与迁移 SQL，已有迁移内容和元数据未修改。
- `api/`：供 Flutter / Web 复用的接口、下单业务、D1 数据访问、认证和支付适配器。
- `backend_web/`：订单、库存和履约管理页面，独立开发和构建入口。

API 路由位于 `web/app/api/v1/`，只做框架入口转发；实现位于 `api/http/`，业务逻辑位于 `api/services/`。以后迁移到独立服务可替换运行适配层，不应复制订单规则。

API 采用同源浏览器策略，没有通配 CORS。Flutter 原生客户端可直接请求 HTTPS API；Flutter 浏览器预览应与 Web 同源，或配置同源反向代理。不要在 App 中放数据库、支付、店主或供应商凭证。

正式开放公共 API 前仍须补充边缘限流/反滥用、客户认证与订单访问令牌、监控，以及数据库库存与商城库存的统一。订单号 + 邮箱的查询沿用当前流程，不是完整客户账户系统。
