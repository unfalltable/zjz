# 管理后台

后台源码位于 `backend/backend_web/`，包含商品、库存、订单、物流设置、售后和操作记录。订单全历史分页查询，收件资料与每件商品可在详情查看；所有页面使用真实数据库，不自动生成演示业务。

在仓库根目录执行：

```sh
npm ci
npm run dev:admin
npm run build:admin
```

开发地址：`http://localhost:5174/`。自托管生产后台为独立构建入口，公网商城拒绝 `/ops` 与 `/api/admin/*`。访问自己的服务器后台须按 [部署说明](../../docs/selfhost-deployment.md#后台访问) 建立 SSH 隧道后打开 `http://localhost:8081/ops`。

两端共用根目录的 Node 依赖和 UI 组件（`web/components/ui`），在根目录安装依赖。后台从 `backend/api/` 读取服务、从 `shared/` 读取类型。

Node 生产环境每次请求验证独立后台凭据与 `STORE_OWNER_ID`，不信任浏览器提交的身份头或店主 ID。未登录、其他店主、公网 Web 面与跨来源私有 API 访问均拒绝；不要把 Sites 的本地模拟器当作生产登录。本轮未修改 `backend/api/user_account/` 或用户管理。

## 实际操作顺序

1. **商品上架**：新建 SKU、名称、USD 售价、展示 URL、分类、图片 URL、三语介绍和包装后重量（克）。新商品默认下架且库存 0；先记录真实入库，再编辑为上架。图片使用 HTTPS 或现有 `/products/` 地址，目前不是文件上传／多规格 SKU 管理器。
2. **物流设置**：先添加真实承运商名称、代码和含 `{trackingNumber}` 的 HTTPS 查询链接；再配置国家、配送方式、首重基础运费、续重费用、免邮门槛与预计天数。当前结算支持美国、加拿大、英国、德国、澳大利亚、法国。保存首条规则后，未覆盖／停用路线不再回退旧价格。新增商品重量默认 500g，仅是待核验估算，必须改成包装后的实际重量。
3. **确认订单**：打开订单详情核对邮箱、电话、地址和商品清单，填写核对说明。待付款订单只能确认资料或取消，不预留、不发货。支付接通后，经可信支付流程核验为已付款的订单才可再次确认并预留库存；后台没有人工“标记已付款”按钮。
4. **发货**：已付款、已确认且库存预留成功后，按平台卖家、自包装、供应商三条路线创建包裹，逐 SKU 填实际数量、承运商和真实运单号。每个包裹只能包含同路线商品，支持分包／部分发货；成功登记才扣对应库存，重复运单或并发冲突整体回滚。可打印拣货单，不是购买承运商面单或税务发票。
5. **物流节点**：逐包裹按已发货 → 运输中 → 已送达记录实际情况，说明必填。订单只有全部商品已发且全部包裹签收才完成。顾客订单号＋结账邮箱查询可看到包裹、运单链接与商家人工节点；这些不是承运商自动扫描轨迹。
6. **售后**：已发商品可受理退货／退款申请，选择 SKU、数量、申请金额和原因；不超过尚未申请的已发数量、商品价值或订单余额。审核拒绝为终态，批准退货后必须验收才能选择合格商品归还库存，不能重复入库。需要退款的案件进入待退款队列，不能假结案或标已退款。未发货的已付款订单取消会释放预留并创建全额待退款记录。

## 边界与安全

- 支付与退款执行持续关闭，不收款、不代客付款；用户模块保持原样。
- 物流商账号/API、面单购买、自动轨迹同步、平台自动采购、换货补发尚未接入，不显示为“已连接”。
- 保存使用版本控制与原子事务；订单、库存、物流配置、售后均记录实际操作。老的只改状态接口已禁止推进，不能绕过真实包裹。
- 上架商品／库存当前加载最多 1000 个 SKU；订单与售后为服务器分页。该版本面向人工运营闭环，不等于大型平台的仓库、多规格、税务、自动化和容量认证。
- 私有凭据只在服务器本机查看，禁止写到代码、日志、聊天或截图。

单独部署时配置 `STOREFRONT_URL=https://你的商城域名`，商城和后台使用同一持久化数据库。生产后台未配置商城地址时不会把“查看商城”误链到后台首页。
