# Web 商城

保留 React / Next 风格路由与 Vinext Worker 部署，避免把消费者商城改成只有 App 式渲染的页面。目录中的 `app/` 是 Web 框架路由约定，不是仓库根目录的 Flutter `app/`。

根目录执行 `npm ci`、`npm run dev:web`、`npm run build:web`。开发地址 `http://localhost:5173/`。

页面：`/` 商城、`/product/:id` 可分享的商品独立详情（SSR 与基础元信息）、`/checkout` 待付款草稿、`/track` 查询、`/ops` 原后台兼容入口。

`/api/v1/catalog`、`/api/v1/orders`、`/api/v1/orders/track` 是共享接口，逻辑由 `backend/api/http/` 承担。

商城读取 D1 实际商品与库存。空库不显示可购买的示例商品；目录请求失败展示错误与重试。需要由后台显式导入商品模板或创建商品、入库后再上架。英/中/西语贯穿商城、详情、购物袋、草稿确认和查询。

目录接口支持分类、三语言检索、价格排序和游标分页（默认 50 / 最大 100 件），商品 SSR 详情按 ID 直接查询。客户端当前完整聚合目录后才更新购物状态，后页失败、重复 ID 或游标、坏分页元数据均报错，不拿部分结果清空购物袋。每次展示 24 件商品，“查看更多”扩大展示窗口；筛选条件改变时从第一组开始。该兼容方案不等于按需百万级搜索，超大目录仍需独立购物袋商品读取与索引搜索。

支付仍暂停：保存草稿不扣款、不预留库存，也不允许推进发货。响应不明确时，同一页面使用原请求确认结果，恢复期间不编辑新请求；个人资料不持久化，跨刷新恢复尚未完善。

构建输出在 `web/dist/`，根目录的构建脚本将它复制为托管所需的 `dist/`，包含 Worker、静态资源、站点配置和 SQLite journal 允许的数据库迁移。MySQL 用户 SQL 不进入托管迁移包。根目录 `.openai/hosting.json` 中的站点 ID 保持不变。

本地环境变量放在 `web/.dev.vars`；不要提交该文件。
